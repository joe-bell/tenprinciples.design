# Review notes

What to check on a pull request to this repo. CI runs `prettier --check` and nothing
else — no tests, no type-check, no build — so review is the only other safety net.
Formatting is already prettier's job and is not repeated here.

## 1. The principles' wording

`src/principles/*.md` is a canonical text, not prose we own. Any edit to it is a content
change, not a copy tweak — check it against the published Vitsœ translation and say which
source you used.

Two entries already diverge from that translation, so know whether a PR is fixing a
deviation or introducing one:

- **04** — "it can make the product clearly express its function by making use of the
  user's intuition" (Vitsœ: "it can make the product talk").
- **10** — "Less, but better. Simple as possible but not simpler. Good design elevates the
  essential functions of a product." (Vitsœ: "Less, but better – because it concentrates on
  the essential aspects, and the products are not burdened with non-essentials.")

Punctuation is part of the text and prettier will not normalise it. `04` mixes a curly
apostrophe (`product’s`) with a straight one (`user's`) in the same file; `07` uses an en
dash. Don't let a PR silently flip these.

Attribution lives in `src/config.ts` (`author`) and is rendered in the `index.astro`
header — it stays on the page.

## 2. Adding or renaming a principle

`src/pages/index.astro` sorts by `Number.parseInt` on the filename prefix and **throws at
build time** if it can't parse one. A new or renamed file must keep the `NN-` prefix.

Each `.md` starts at `##`: the page's only `<h1>` is the site title, and the list-item
styles target `*:[h2]` and `*:[p]` directly. A `#` heading breaks both the outline and the
styling.

`src/content.config.ts` defines the collection with a glob loader and **no schema**, so
nothing validates content shape. That check is yours.

## 3. CI does not build the site

`pnpm build` is `build:css && astro check && astro build`. For anything touching `src/`,
run it locally before approving.

Tailwind is a separate step: `build:css` writes `src/styles/output.css`, which is gitignored
and inlined into every page via `?raw` in `src/layouts/root.astro`. A bad class name or a
stale/missing `output.css` therefore surfaces at deploy, not in the diff.

## 4. `src/pages/api/event.ts`

The only non-prerendered route on the site (`prerender = false`) — a POST proxy that
forwards to a hardcoded `plausible.io` endpoint with the `cookie` header stripped.

Keep the target URL a literal, keep the cookie deletion, and don't widen it to other methods
or caller-supplied destinations. This is a public domain; a caller-controlled target makes
it an open proxy.

## 5. Design and accessibility

Neither CI nor a type-check sees any of this, and it is the whole point of the site.

- **Focus:** there are no custom focus styles anywhere in `src/` — links rely on the browser
  default outline. A PR that restyles links must not remove it.
- **Both themes:** colour is `dark:` variant pairs (zinc-800 on zinc-50, zinc-300 on
  zinc-950) plus `--color-braun` (`#e99d39`) from `src/styles/input.css`. Check contrast in
  light _and_ dark.
- **Motion:** the existing pattern is `motion-safe:scroll-smooth`. New motion goes behind
  `motion-safe:` too.
- **Layout:** the list uses Tailwind 4 arbitrary properties (`[---gap:2rem]`,
  `gap-y-(---gap)`) and `max-w-[45ch]`. Check the 1 → 2 → 5 column breakpoints and that
  the leading-zero markers still line up.
- The 404 page calls a global `plausible(...)`; the tracker is initialised through the
  `@plausible-analytics/tracker` `init()` import. If you touch either, confirm that global
  actually exists.

## 6. Pull requests from outside contributors

- `.github/workflows/ci.yml` triggers on `pull_request`, so fork PRs run without repo
  secrets. It must not become `pull_request_target`.
- `worker-configuration.d.ts` is generated by `wrangler types` (wired through
  `lint-staged.config.mjs`) and is prettier-ignored. Changes there should be regenerated
  output, never hand edits.
- `.npmrc` sets `save-exact=true`. Dependency changes should land as exact versions with a
  matching `pnpm-lock.yaml`.
